# 📚 STM32 智能车学习路线图

> 这是我从零开始学习 STM32 智能车的完整学习路线，历时约 2 个月。每个阶段都有对应的知识点、练习项目和我当时踩过的坑，希望能帮到后来的同学。

---

## 🎯 前置知识

在开始之前，建议你先掌握这些基础知识：

- C 语言基础（指针、结构体、位操作）
- 基本的电路知识（欧姆定律、串并联、二极管、三极管）
- 数电模电基础（有最好，没有也能边做边学）
- 会用万用表、示波器（没有也没关系，万用表必备）

## 第一阶段：STM32 入门基础（1~2 周）

### 学习目标
- 了解 STM32 的基本架构和开发流程
- 掌握 GPIO 输入输出
- 掌握定时器基本使用

### 知识点清单

| 知识点 | 重要程度 | 说明 |
|:------:|:--------:|------|
| STM32 芯片架构 | ⭐⭐⭐ | 内核、总线、外设映射 |
| 开发环境搭建 | ⭐⭐⭐ | Keil MDK / STM32CubeMX 安装配置 |
| GPIO 原理 | ⭐⭐⭐ | 推挽输出、开漏输出、上拉下拉输入 |
| 定时器基础 | ⭐⭐⭐ | 时基单元、预分频、自动重装载 |
| 中断系统 | ⭐⭐ | NVIC、中断优先级 |
| 时钟树 | ⭐⭐⭐ | HSI/HSE/PLL、系统时钟配置 |

### 练习项目

1. **点亮 LED** - 第一个程序，让一个 LED 闪烁起来
   - 难度：⭐
   - 目的：熟悉开发环境和烧录流程
   - 要点：GPIO 输出模式配置

2. **按键扫描** - 用按键控制 LED 亮灭
   - 难度：⭐⭐
   - 目的：GPIO 输入、按键消抖
   - 要点：上拉输入、软件消抖 vs 硬件消抖

3. **蜂鸣器音乐** - 用蜂鸣器播放一首简单的曲子
   - 难度：⭐⭐
   - 目的：定时器中断、频率控制
   - 要点：定时器中断配置、音符频率表

4. **定时器闪烁** - 用定时器中断实现 LED 精确闪烁
   - 难度：⭐⭐
   - 目的：定时器时基配置、中断服务函数
   - 要点：预分频系数计算、自动重装载值计算

### 我踩过的坑

> 💣 **坑 1**：时钟配置错了导致串口乱码。H7 的时钟树真的很复杂，建议直接用 CubeMX 生成配置，别自己手写。
>
> 💣 **坑 2**：按键消抖没做好，按下一次触发好几次。一开始用的延时消抖，太占 CPU 了，后来改成定时器扫描就好多了。
>
> 💣 **坑 3**：下载器连不上。检查 BOOT 引脚接线、检查驱动、检查 Keil 里的调试器配置，这三个地方最容易出问题。

### 推荐学习资源
- 正点原子 STM32H7 教程（前 10 讲）
- STM32 参考手册（GPIO 和定时器章节）

## 第二阶段：PWM + 电机控制（1 周）

### 学习目标
- 理解 PWM 原理
- 掌握定时器 PWM 输出
- 学会驱动直流电机

### 知识点清单

| 知识点 | 重要程度 | 说明 |
|:------:|:--------:|------|
| PWM 原理 | ⭐⭐⭐ | 占空比、频率、分辨率 |
| 定时器 PWM 模式 | ⭐⭐⭐ | 比较输出、PWM 模式 1/2 |
| 电机驱动原理 | ⭐⭐⭐ | H 桥、正反转、调速 |
| TB6612/L298N | ⭐⭐⭐ | 驱动芯片使用方法 |

### 练习项目

1. **呼吸灯** - 用 PWM 实现 LED 渐亮渐灭
   - 难度：⭐⭐
   - 目的：掌握 PWM 输出配置
   - 要点：占空比动态调整

2. **电机调速** - 用 PWM 控制电机转速
   - 难度：⭐⭐
   - 目的：PWM 驱动电机
   - 要点：TB6612 接线、PWM 频率选择（建议 10~20kHz）

3. **小车基础运动** - 实现前进、后退、左转、右转、停止
   - 难度：⭐⭐⭐
   - 目的：差速转向原理
   - 要点：左右轮速度差控制转向半径

### 我踩过的坑

> 💣 **坑 1**：电机一启动单片机就复位。这是因为电机启动电流大，拉低了电源电压。解决方案：电机和单片机分开供电，共地不共电源。
>
> 💣 **坑 2**：PWM 频率太低，电机有刺耳的啸叫声。把频率调到 15kHz 以上就听不到了（人耳听觉范围 20Hz~20kHz）。
>
> 💣 **坑 3**：L298N 发热严重，效率太低。后来换成 TB6612 就好多了，体积小还不怎么发热。

## 第三阶段：编码器 + 速度闭环（1~2 周）

### 学习目标
- 理解编码器原理
- 掌握定时器编码器模式
- 学会 PID 控制算法基础

### 知识点清单

| 知识点 | 重要程度 | 说明 |
|:------:|:--------:|------|
| 编码器原理 | ⭐⭐⭐ | 增量式编码器、AB 相、线数 |
| 定时器编码器模式 | ⭐⭐⭐ | 编码器接口、4 倍频 |
| 测速方法 | ⭐⭐⭐ | M 法、T 法、M/T 法 |
| PID 控制基础 | ⭐⭐⭐ | 比例、积分、微分的作用 |
| 位置式 PID | ⭐⭐⭐ | 公式推导和实现 |
| 积分饱和 | ⭐⭐ | 产生原因和解决方法 |

### 练习项目

1. **编码器读数** - 读取编码器数值，判断正反转
   - 难度：⭐⭐
   - 目的：定时器编码器模式配置
   - 要点：编码器接线（A相、B相、5V、GND）、4 倍频计数

2. **速度计算** - 根据编码器数值计算电机转速
   - 难度：⭐⭐
   - 目的：掌握 M 法测速
   - 要点：采样周期选择、转速单位换算（rpm / cm/s）

3. **单电机 PID 调速** - 用 PID 让电机稳定在目标转速
   - 难度：⭐⭐⭐
   - 目的：理解 PID 控制原理
   - 要点：PID 参数整定方法（先 P 后 I 再 D）

4. **双轮速度同步** - 左右轮用独立 PID，保证速度一致
   - 难度：⭐⭐⭐
   - 目的：差速控制基础
   - 要点：两个 PID 控制器独立工作

### 我踩过的坑

> 💣 **坑 1**：编码器方向反了。可以在软件里改，也可以把 A/B 相线反接。
>
> 💣 **坑 2**：PID 参数怎么调都不对。后来才知道是因为没有看到实时的速度曲线，全靠感觉调当然调不好。建议用串口把数据发到上位机，用 Excel 或者 SerialPlot 画曲线。
>
> 💣 **坑 3**：积分饱和导致超调严重。加上积分限幅和积分分离之后就好多了。

### PID 参数调试心得

1. **先调 P**：从小到大增加 Kp，直到系统开始振荡
2. **再加 I**：慢慢增加 Ki，消除静差，但不要太大，否则超调
3. **最后加 D**：适当增加 Kd，抑制振荡，但 D 太大会放大噪声
4. **口诀**：
   - 参数整定找最佳，从小到大顺序查
   - 先是比例后积分，最后再把微分加
   - 曲线振荡很频繁，比例度盘要放大
   - 曲线漂浮绕大湾，比例度盘往小扳

### 推荐学习资源
- 《自动控制原理》PID 章节
- B站搜索 "PID 调参"，有很多可视化的讲解
- Arduino PID 库文档（原理讲得很清楚）

### 知识点清单

| 知识点 | 重要程度 | 说明 |
|:------:|:--------:|------|
| 超声波测距原理 | ⭐⭐⭐ | 声波反射、时间差计算距离 |
| HC-SR04 使用 | ⭐⭐⭐ | Trig 触发、Echo 回波测量 |

### 练习项目

1. **超声波测距** - 读取距离值并通过串口打印
   - 难度：⭐⭐
   - 目的：HC-SR04 使用方法
   - 要点：定时器输入捕获或者延时测量

2. **红外循迹检测** - 五路红外检测黑线位置

   - 要点：阈值校准、环境光影响

3. **MPU6050 数据读取** - 通过 I2C 读取加速度和角速度
   - 难度：⭐⭐⭐
   - 目的：I2C 通信、传感器寄存器操作
   - 要点：I2C 地址确认、寄存器配置、数据格式转换

4. **加速度计算角度** - 用加速度计计算俯仰角和横滚角
   - 难度：⭐⭐⭐
   - 目的：理解加速度计测角原理
   - 要点：atan2 函数、弧度转角度

5. **陀螺仪积分** - 用陀螺仪积分得到角度
   - 难度：⭐⭐
   - 目的：理解陀螺仪测角原理
   - 要点：零偏校准、积分漂移问题

### 我踩过的坑

> 💣 **坑 1**：MPU6050 I2C 地址不对。有的模块是 0x68，有的是 0x69，取决于 AD0 引脚怎么接。可以用 I2C 扫描程序扫一下。
>
> 💣 **坑 2**：超声波数据跳变厉害。有时候会测到很离谱的值，加个滑动平均滤波就好多了，另外还要做异常值剔除。
>
> 💣 **坑 3**：陀螺仪零漂严重。静止不动放一会儿，角度能飘好几度。一定要做零偏校准，上电的时候取几百个数据求平均值作为零偏。
>
> 💣 **坑 4**：加速度计测的角度抖得厉害。因为加速度计对振动很敏感，电机一转数据就乱跳，需要滤波。

### 推荐学习资源
- MPU6050 数据手册和寄存器手册
- 正点原子 I2C 实验
- InvenSense 官方应用笔记（MPU6050 相关）

## 第五阶段：PID 进阶 + 卡尔曼滤波（2~3 周）

### 学习目标
- 掌握增量式 PID
- 理解积分分离、抗积分饱和等改进算法
- 理解卡尔曼滤波原理
- 实现加速度计和陀螺仪的数据融合

### 知识点清单

| 知识点 | 重要程度 | 说明 |
|:------:|:--------:|------|
| 位置式 vs 增量式 | ⭐⭐⭐ | 两种 PID 的区别和适用场景 |
| 积分分离 | ⭐⭐⭐ | 大偏差时停止积分，防止饱和 |
| 抗积分饱和 | ⭐⭐ | 积分限幅、遇限削弱积分 |
| 卡尔曼滤波原理 | ⭐⭐ | 预测 + 更新、状态估计 |
| 二阶卡尔曼 | ⭐⭐⭐ | 角度 + 零偏两个状态量 |
| 互补滤波 | ⭐⭐ | 简单理解传感器融合 |
| 姿态解算 | ⭐⭐⭐ | Pitch/Roll 角度计算 |

### 练习项目

1. **增量式 PID 实现** - 用增量式 PID 做电机调速
   - 难度：⭐⭐
   - 目的：理解增量式 PID 的优势
   - 要点：增量公式推导、输出累加

2. **积分分离 PID** - 实现带积分分离的位置式 PID
   - 难度：⭐⭐
   - 目的：解决大偏差时积分饱和问题
   - 要点：阈值选择、积分启停逻辑

3. **互补滤波融合** - 用互补滤波融合加速度计和陀螺仪
   - 难度：⭐⭐⭐
   - 目的：理解传感器融合思想
   - 要点：高通 + 低通 = 互补、权重系数选择

4. **卡尔曼滤波融合** - 用卡尔曼滤波得到更稳定的姿态角
   - 难度：⭐⭐⭐⭐
   - 目的：掌握卡尔曼滤波在实际中的应用
   - 要点：Q/R 参数调优、dt 精度

### 我踩过的坑

> 💣 **坑 1**：卡尔曼滤波的公式太复杂，看不懂。我的建议是：先不要纠结数学推导，找一个现成的 C 语言实现，跑起来再说。调参数的过程中慢慢就理解了。
>
> 💣 **坑 2**：Q 和 R 参数不知道怎么调。Q 是过程噪声（相信预测模型的程度），R 是测量噪声（相信测量值的程度）。Q 越大，越相信测量值，响应越快但噪声大；R 越大，越相信预测，越平滑但滞后大。
>
> 💣 **坑 3**：dt 不准导致角度漂移。卡尔曼滤波的 dt 一定要准确，最好用定时器中断来保证精确的采样周期。
>
> 💣 **坑 4**：加速度计和陀螺仪的数据单位没搞对。加速度计是 g，陀螺仪是 deg/s 或者 rad/s，融合的时候单位要统一。

### 卡尔曼滤波调参经验

1. 先把 Q_angle 和 Q_bias 设小一点，R_measure 设大一点，看看效果
2. 如果角度太抖，加大 R_measure（更相信预测）
3. 如果角度滞后严重，减小 R_measure（更相信测量）
4. 如果零漂严重，减小 Q_bias（零偏变化慢）
5. 最终目标：响应快、噪声小、不漂移

### 推荐学习资源
- 《卡尔曼滤波原理及应用》- 讲原理的书
- B站 "DR_CAN" 卡尔曼滤波系列视频 - 讲得通俗易懂
- GitHub 上的 Kalman 滤波 C 语言实现 - 参考代码

| 知识点 | 重要程度 | 说明 |
|:------:|:--------:|------|
| 状态机设计 | ⭐⭐⭐ | 多模式切换逻辑 |
| 时间片轮询 | ⭐⭐⭐ | 基于时基的任务调度 |

| 系统调试方法 | ⭐⭐⭐ | 分步调试、问题定位 |

### 练习项目

1. **循迹模式** - 红外循迹 + PID 转向，让小车沿黑线走
   - 难度：⭐⭐⭐
   - 目的：综合应用红外传感器和 PID
   - 要点：差速转向、路径识别逻辑

   - 难度：⭐⭐⭐

   - 要点：障碍物判断逻辑、转向策略

3. **蓝牙遥控** - 通过蓝牙模块接收指令控制小车

4. **OLED 显示** - 在 OLED 上显示车速、姿态、电压等信息
   - 难度：⭐⭐

   - 要点：字模生成、多页显示

5. **模式切换** - 实现多种运行模式的切换
   - 难度：⭐⭐⭐
   - 目的：状态机设计
   - 要点：模式切换时的资源清理和状态重置

### 我踩过的坑

> 💣 **坑 1**：所有代码都塞在 main 函数里，越写越乱，最后自己都看不懂了。一定要模块化，每个模块一个 .c 和 .h 文件，通过函数接口调用。
>
> 💣 **坑 2**：任务调度混乱，有的任务执行太频繁，有的又太久没执行。用时间片轮询法，给每个任务分配固定的执行周期，清晰多了。
>
> 💣 **坑 3**：模式切换的时候 PID 没有重置，导致切换后小车乱跑。切换模式的时候一定要把相关的状态都清掉。
>
> 💣 **坑 4**：整合的时候各种 bug 都冒出来了。还是那句话，**每个模块单独调试好再整合**，别一口气全写完再调，那时候根本不知道问题在哪。
