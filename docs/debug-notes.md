## 硬件相关

### 问题 1：电机启动时单片机复位 / 死机

**现象**：电机一启动，单片机就复位或者卡死，有时候还会出现奇怪的行为。

**排查过程**：
1. 一开始以为是软件 bug，单步调试发现程序跑飞的位置不固定
2. 用万用表测电源电压，发现电机启动瞬间 3.3V 会掉到 2.8V 左右
3. 确认是电源问题——电机启动电流太大，拉低了电源电压

**解决方案**：
- ✅ 电机和单片机分开供电（电机用 7.4V 锂电池，单片机用 5V 稳压）
- ✅ 电源入口加 1000uF 电解电容 + 0.1uF 陶瓷电容滤波
- ✅ 电机电源线上加磁环，减少电磁干扰
- ✅ 驱动板和主控板之间用光电隔离（可选，我没加也能正常用了）

**经验总结**：
> 大电流器件一定要和控制电路分开供电！共地不共电源是基本原则。
> 我最开始图省事用同一个电源，结果栽了个大跟头，折腾了一周才彻底解决。

### 问题 2：MPU6050 I2C 通信经常卡死

**现象**：MPU6050 数据读取时有时无，有时候跑着跑着就卡死在 I2C 通信上了。

**排查过程**：
1. 用逻辑分析仪抓 I2C 波形，发现有时候 SDA 线被拉低之后就不释放了
2. 检查硬件，发现模块上自带的上拉电阻是 10K 的
3. 换了个 MPU6050 模块还是一样的问题

**解决方案**：
- ✅ 将 I2C 上拉电阻改为 4.7K（原来的 10K 太大了，上升沿太慢）
- ✅ 缩短 I2C 走线长度（原来的杜邦线太长了，有 20cm）
- ✅ 软件增加 I2C 超时检测和总线恢复机制
- ✅ I2C 时钟频率从 400kHz 降到 100kHz（虽然慢了点但稳定）

**经验总结**：
> I2C 的上拉电阻阻值很重要，不是越大越好也不是越小越好。
> 一般标准模式（100kHz）用 4.7K~10K，高速模式（400kHz）用 1K~4.7K。
> 走线太长的话建议降低通信速率。

### 问题 3：超声波测距数据跳变严重

**现象**：超声波测出来的距离忽大忽小，有时候明明障碍物没动，数值却跳了几十厘米。

**排查过程**：
1. 用示波器看 Echo 引脚波形，发现确实有时候会有异常的回波
2. 怀疑是环境干扰或者多次反射
3. 在不同环境下测试，发现开阔地好一些，墙角附近跳变更严重

**解决方案**：
- ✅ 软件加滑动平均滤波（取最近 5 次数据的平均值）
- ✅ 加异常值检测：如果当前值和上次值相差超过 30cm，直接丢弃
- ✅ 多次测量取中值（测 5 次，去掉最大最小，取中间 3 次的平均）
- ✅ 超声波安装位置调整，避免和地面太近（地面反射干扰）

**经验总结**：
> 超声波数据不稳定是常态，一定要做滤波。
> 另外超声波有最小测距限制（一般 2cm），太近了测不准。
> 还有就是光滑斜面容易产生镜面反射，接收不到回波。

### 问题 4：OLED 显示乱码 / 花屏

**现象**：OLED 有时候显示不正常，字符错位或者有乱码点。

**排查过程**：
1. 检查字模数据，确认没问题
2. 用逻辑分析仪看 I2C/SPI 波形，发现有丢包
3. 怀疑是通信速率太高或者干扰

**解决方案**：
- ✅ 降低 SPI/I2C 通信速率
- ✅ 初始化后加一段延时再开始显示
- ✅ 增加显示缓冲区，整屏刷新而不是局部反复刷
- ✅ 检查电源稳定性，OLED 对电源纹波比较敏感

## 软件相关

### 问题 5：串口打印乱码

**现象**：串口助手收到的数据全是乱码，根本看不懂。

**排查过程**：
1. 检查波特率设置，Keil 里和串口助手都设的是 115200
2. 还是不对，试着改了几个波特率，9600 也不对
3. 突然想到会不会是系统时钟配置错了

**解决方案**：
- ✅ 重新检查系统时钟配置，发现 HSE_VALUE 宏定义不对
- ✅ 用 STM32CubeMX 重新生成时钟配置代码
- ✅ 串口波特率设置和时钟树一定要对应

**经验总结**：
> 串口乱码 99% 的情况是波特率不对，而波特率不对的根本原因往往是系统时钟配置错了。
> H7 的时钟树很复杂，建议直接用 CubeMX 配置，别自己手写。
> 可以用 LED 闪烁或者延时函数来大致验证时钟频率对不对。

### 问题 6：printf 不输出 / 进 HardFault

**现象**：想用 printf 打印调试信息，结果什么都不输出，有时候还会直接进 HardFault。

**排查过程**：
1. 检查串口初始化，确认没问题
2. 查了一下，printf 需要重定向 fputc 函数
3. 加了 fputc 之后还是不行，进 HardFault 了

**解决方案**：
- ✅ 实现 fputc 函数重定向到串口：
  ```c
  int fputc(int ch, FILE *f)
  {
      HAL_UART_Transmit(&huart1, (uint8_t *)&ch, 1, 0xFFFF);
      return ch;
  }
  ```
- ✅ Keil 里勾选 "Use MicroLIB"（不勾选的话 printf 可能会有问题）
- ✅ 如果不用 MicroLIB，也可以自己实现 _sys_open 等系列函数

**经验总结**：
> STM32 用 printf 一定要重定向，而且要注意 MicroLIB 的设置。
> 另外打印浮点数的话可能还需要额外设置，或者自己写个转换函数。

### 问题 7：定时器中断不进 / 进了就出不来

**现象**：配置了定时器中断，但是断点调试发现根本进不了中断服务函数。

**排查过程**：
1. 检查定时器初始化代码，看起来没问题
2. 检查 NVIC 配置，发现中断使能没开
3. 还有一次是中断服务函数名写错了

**解决方案**：
- ✅ 确保 `HAL_TIM_Base_Start_IT()` 被调用了
- ✅ 确保 NVIC 里配置了定时器中断优先级并且使能了
- ✅ 中断服务函数名要和启动文件里的一致（注意拼写！）
- ✅ 中断里不要放太多代码，快进快出
- ✅ 如果一直进中断出不来，检查中断标志位有没有清除

**经验总结**：
> 中断不进一般就三个原因：外设没初始化对、NVIC 没使能、函数名写错了。
> 一个一个排查就行。

### 问题 8：变量被意外修改 / 内存越界

**现象**：某个变量的值莫名其妙就变了，逻辑上根本说不通。

**排查过程**：
1. 用 debugger 观察变量，发现每次都是在某个函数执行后变的
2. 检查那个函数，发现有个数组写越界了
3. 越界写到了后面变量的内存地址

**解决方案**：
- ✅ 检查所有数组操作，确保不会越界
- ✅ 全局变量比较多的话，可以用结构体组织起来
- ✅ 定义数组的时候多留一点余量
- ✅ 可以用 MPU（内存保护单元）来检测越界访问（H7 支持）

**经验总结**：
> 变量值莫名其妙变化，大概率是内存越界或者野指针。
> C 语言没有边界检查，写代码的时候一定要自己注意。

## 算法相关

### 问题 9：PID 调速抖动厉害

**现象**：电机速度波动很大，能听到明显的抖动声，速度曲线像锯齿一样。

**排查过程**：
1. 打印速度曲线，发现波动频率和 PID 控制频率差不多
2. 怀疑是 P 太大或者 D 太大
3. 尝试减小 P，抖动变小了但响应变慢了

**解决方案**：
- ✅ 降低 Kp，减小比例增益
- ✅ 适当降低 Kd，微分项会放大噪声
- ✅ 增加速度采样的滤波（滑动平均）
- ✅ 提高 PID 控制频率（从 50Hz 提到 100Hz）
- ✅ 如果还是抖，可以考虑加个死区

**经验总结**：
> PID 调参真的是经验活，说几个我总结的小技巧：
> 1. 先只加 P，从小到大，找到开始振荡的那个值，然后取一半作为起点
> 2. 再加 I，从小加起，只要能消除静差就行，别太大
> 3. 最后加 D，也是从小加起，能抑制振荡就行
> 4. 一定要用串口把数据打出来看曲线，光靠眼睛看小车是调不准的

### 问题 10：PID 积分饱和导致超调严重

**现象**：目标速度变化大的时候，电机速度会超调很多，然后慢慢振荡回来。

**排查过程**：
1. 观察积分项的值，发现偏差大的时候积分累积得很大
2. 即使误差反向了，积分项还需要好一会儿才能降下来
3. 这就是典型的积分饱和现象

**解决方案**：
- ✅ 加积分限幅：积分项累积到一定值就不再增加了
- ✅ 加积分分离：当误差大于某个阈值时，暂停积分
- ✅ 遇限削弱积分：当输出已经饱和时，反向误差才积分，同向误差不积分

**我用的积分分离代码**：
```c
// 积分分离：只有误差比较小的时候才积分
if (pid->integral_separation_enabled) {
    if (fabsf(pid->error) < pid->integral_threshold) {
        pid->integral += pid->error;
    }
} else {
    pid->integral += pid->error;
}
```

### 问题 11：卡尔曼滤波角度漂移

**现象**：小车静止不动，卡尔曼滤波输出的角度却在慢慢变化，有漂移。

**排查过程**：
1. 先检查是不是陀螺仪本身的零漂——静止时读取陀螺仪数据，确实有微小输出
2. 然后检查 dt 是否准确——发现我用的是 HAL_Delay，不够精确
3. 最后检查卡尔曼参数，Q_bias 太大了

**解决方案**：
- ✅ 陀螺仪零偏校准：上电时静止采集 500 次数据取平均值作为零偏
- ✅ 用定时器中断来保证精确的采样周期，不要用 HAL_Delay
- ✅ 调整 Q_bias 参数，调小一点（零偏变化是很慢的）
- ✅ 确认加速度计计算的角度是对的，卡尔曼会慢慢收敛到加速度计的值

**经验总结**：
> 卡尔曼滤波的角度漂移通常有几个原因：
> 1. 陀螺仪零偏没校准好 → 上电校准
> 2. 采样周期 dt 不准 → 用定时器
> 3. Q_bias 太大 → 调小 Q_bias
> 4. R_measure 太大，太不相信加速度计了 → 适当减小 R
>
> 正常来说，静止时角度应该是稳定的，漂移量应该非常小。

## 传感器相关

### 问题 12：MPU6050 角度不准 / 倾斜时误差大

**现象**：把模块水平放着角度是对的，但是倾斜大了之后误差就变大了。

**排查过程**：
1. 检查加速度计的角度计算公式
2. 发现我最开始用的是 atan 函数，而不是 atan2
3. atan 的范围只有 -90°~90°，超过就不对了

**解决方案**：
- ✅ 用 atan2 代替 atan，返回值范围 -180°~180°
- ✅ 正确的俯仰角计算公式：
  ```c
  pitch = atan2(acc_y, acc_z) * 180.0f / PI;
  roll  = atan2(-acc_x, sqrt(acc_y*acc_y + acc_z*acc_z)) * 180.0f / PI;
  ```
- ✅ 加速度计需要校准（零偏和灵敏度）

### 问题 13：红外循迹在不同光线下误判

**现象**：同一个地面，上午测着好好的，下午太阳照进来就不准了。

**排查过程**：
1. 读取红外传感器的原始 AD 值，发现不同光线下基线差很多
2. 固定阈值的方式在光线变化时失效

**解决方案**：
- ✅ 增加自动校准功能：上电时自动检测地面的基准值
- ✅ 使用相对阈值而不是绝对阈值（比如和基准值的差值百分比）
- ✅ 五路红外做交叉验证，提高判断可靠性
- ✅ 如果环境光线变化大，考虑用带调制的红外传感器

---

### 问题 14：编码器计数不准 / 方向判断错误

**现象**：电机转一圈，编码器计数和理论值对不上，或者方向偶尔判错。

**排查过程**：
1. 检查定时器编码器模式配置
2. 用示波器看 A/B 相波形，确认相位差是 90°
3. 发现有时候有毛刺，导致误计数

**解决方案**：
- ✅ 确认定时器编码器模式配置正确（TI1 和 TI2 都计数，4 倍频）
- ✅ 编码器信号线用屏蔽线，减少干扰
- ✅ 如果干扰严重，可以加硬件滤波（RC 低通）
- ✅ 软件也可以做简单的校验，比如转速突变时做限幅

## 📝 调试技巧总结

做了这么久的项目，总结了一些调试的小技巧：

### 硬件调试
1. **万用表是神器** - 电源对不对、通不通、电压正不正常，先测了再说
2. **逻辑分析仪很有用** - 通信类问题（I2C/SPI/UART）抓波形一看就清楚
3. **示波器更直观** - 模拟信号、电源纹波、PWM 波形，示波器一看便知
4. **替换法排故** - 怀疑某个模块坏了，换个好的试试就知道了

### 软件调试
1. **printf 调试法** - 虽然low但真的好用，把关键变量都打出来
2. **断点调试** - 配合 ST-Link，可以单步执行看寄存器和变量
3. **二分法定位** - 不知道 bug 在哪，就注释一半代码，看问题还在不在
4. **看调用栈** - 跑飞了或者进 HardFault 了，先看看调用栈

### 经验之谈
1. **分步调试，逐步集成** - 每个模块单独调好再整合，别一口气全写完再调
2. **做好版本管理** - 能用 Git 最好，不行的话多备份几个版本
3. **记录问题和解决方法** - 好记性不如烂笔头，下次遇到直接查
4. **休息一下再回来** - 卡壳的时候别死磕，出去走走，说不定就想通了
